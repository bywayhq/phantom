## Independent backup and error preservation

ready_resources320-335 constructs the concrete resource owner BEFORE server
acquisition and wraps all setup/body outcomes. Backup227-316 starts only when
control exits; every target closure or cause oracle runs earlier.

Backup requests cancellation only for its actual unfinished owned target/
controller tasks. It calls unmodified protocol base close and base wait_closed
under independent five-second bounds; controlled subclass fault hooks are
bypassed. A synchronous finally always closes both retained transports.
It cancels actual protocol timer/transmit handles if termination failed.

It then finitely observes owned tasks and each endpoint connection_lost/socket
closure. Previously retrieved immutable Task outcomes are not counted twice;
only own-requested Task cancellation is ignored. Actual unobserved returned
exceptions and failed owned Future results are retained, with no broad
exception-type filter for ordinary errors.

If both target assertion and backup fail, the target object remains the
top-level result and test_backup_failure holds BackupFailure.failures with
the original backup objects. Its existing cause is not overwritten.
If backup alone fails, BackupFailure is raised.

No backup can prove arbitrary network tasks always stop. An unfinished actual
owned task produces explicit backup failure. Individual waits are finite;
there is no claim of one universal five-second total cleanup bound.
