Timeout is a distinct boundary. --timeout is parsed as float with no finite check and is added to scenario.page_milliseconds before waiting for run.done. An infinite allowance therefore installs an infinite wait deadline in the inspected CPython loop scheduling path; no finite watchdog event can become due at finite loop time. This is a supported finite-bound validation candidate, without an observed hang. NaN is also accepted by float conversion without an explicit finite policy, but exact runtime timing behavior was not measured. No arbitrary maximum is justified. A blanket timeout>0 requirement is not yet established: zero is an extra allowance atop the scenario's positive programmed waits, and the source/docs do not define whether zero margin is forbidden. Negative allowances can shorten or eliminate the derived wait; that is an input-policy question, not evidence of a successful empty capture. Manifest timeout is a separate whole-job budget, not automatically the same CLI allowance. Recommend explicit finite CLI/derived-budget validation and a documented margin policy before a causal timeout control; do not equate the manifest's positive-budget rule with this allowance.
