# Failed QUIC close: independent pinned-source diagnosis

A failed protocol cleanup needs public UDP transport abort and explicit ownership of the protocol handles still scheduled at that failure. Successful protocol close/wait should keep graceful transport close. This is a bounded source proposal, not a tested remedy.

Both complete root71d logs and revision/exit receipts were read after root's terminal notice. Linux selected eight: six pass and nested/self-reference fail at 513/535. Windows has five pass, those two failures and an old close-fault timeout at 355 awaiting connection_lost after is_closing passed. Its later warning shows a closing Proactor UDP transport with finished write30. The warning is consistent with the path but does not independently identify the exact target object.

ObservedProtocol96-100 calls actual base close before injecting its fault. aioquic sends the close datagram synchronously and arms its timer. The helper catches, skips wait_closed and closes UDP immediately. Proactor close103-112 increments _conn_lost and does not schedule connection_lost when a write future exists. Its write callback511-514 then returns before clearing the future or scheduling loss. Repeated close returns. This accounts for the actual timeout and finished-write state without claiming natural-fault provenance.

Public DatagramTransport.abort calls _force_close(None), clears/cancels pending IO and schedules loss(None), including while already closing. Select it on failed protocol cleanup, not merely on an initiating body exception. Also cancel actual non-None protocol._timer/_transmit_task handles before abort in the exceptional path; the current finite backup already recognizes these concrete pinned owners. Preserve all cause objects and abort errors using the separately reviewed composition, with no new detached task or longer deadline.

Add an actual pre-backup timer control before claiming this scheduled-work repair: retain the TimerHandle armed by the real base close before the sentinel, then require that exact armed handle is cancelled and real transport loss/socket closure occur before backup. UDP abort does not mean QUIC termination. In this controlled post-close path CLOSING is an END_STATE, so a later timer's datagrams_to_send is empty; a timer-send-to-closed-socket error is not measured. transmit resets _transmit_task without cancelling previously queued handles, so cancellation of its current field does not prove ownership of every historical queued callback. That wider case needs its own actual queued-handle control.
