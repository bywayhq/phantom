## Findings

- Major: four original coordinators and their children discard result handles
  (66-80,96-113,131-148,324-341). HTTP2/3 child Result failures are never joined.
- Major: HTTP1 and held-limit loops silently accept read/write failures. TCP
  accept loops hide any error. Held-worker seen and release-wait failures are
  also discarded (67-77,97,325-339).
- Major: three contextual deadline maps discard the original Elapsed cause
  (172,269,298). Body collection already preserves it. The expected 300ms
  held-window timeout is a positive oracle and must retain its current meaning.
- Major: held-limit `seen.recv_timeout(...)?` bypasses explicit release and
  original thread join. Automatic scoped joining then waits for the original
  first request's timeout and discards its returned Result. The later explicit
  first.join failure also bypasses the independently computed waited outcome
  (346-365). Neither original thread is detached; this is release/error handling.
- Minor: local imports precede standard and external groups (10-38). Group them
  with the other local imports during the owned semantic slice.

Runtime destruction genuinely shuts down these async coordinators and children.
Resolved Tokio 1.53.1 Runtime::new creates a multi-thread runtime; Drop closes
its scheduler, and workers shut down owned tasks. This is distinct from losing
original outcomes while that runtime lives. A current-thread client's kept
runtime suspends its drivers after block_on and resumes them if block_on is
called again. Its deliberate Drop is also real shutdown. Preserve both modes.
No permanent leak, native result or production runtime defect is claimed.
