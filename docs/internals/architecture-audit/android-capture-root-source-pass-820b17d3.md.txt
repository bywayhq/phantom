## Accepted findings

1. A refused session invokes unconditional exit cleanup. Both refusal paths
   precede acquisition, yet exit force-stops the selected browser. Existing
   refusal controls exclude clearing, killing and starting but omit this
   command. The missing contract is no mutation before an accepted launch.
2. Configuration ownership is recorded after the entire `push_text` call.
   A successful push followed by temporary-directory cleanup or chmod failure
   leaves the uploaded path outside session cleanup. Test the actual canonical
   push helper with a modeled command boundary and remote-file witness.
3. Exit attempts cleanup serially. An escaped action failure skips later
   resources. During failed entry it can replace the initiating top-level
   exception. The existing outer launcher already retains a body error when
   session cleanup escapes; that supported behavior must remain intact.
4. Nonpositive direct `typing_attempts` permits setup followed by no open
   attempt. Validate before device effects. Ordinary CLI dispatch uses the
   default three attempts; this finding concerns direct construction.
5. Android launch and exit use blocking commands and sleeps on the serving
   event loop. Moving launch to an executor also needs owned completion and
   async exit/cancellation handling. Source review establishes reachable
   blocking, not a measured deadlock, dropped capture or device failure.

Synchronous lifecycle controls are being authored separately from async-loop
controls. Reproduction and remedies remain pending. No wrapper representation
is prescribed by direct-session baseline controls.

## Standards and retained limits

Configuration preserves argument/preference order. Typed navigation waits for
the exact URL before submitting; existing timeout-zero controls remain valid.
Resolver rewriting and reverse mapping have distinct TCP/UDP contracts.
XML helpers return absence for malformed dumps; their trusted subprocess-input
assumptions are not packet or browser validation. Refusal exceptions convey the
explicit physical-device/cold-boot opt-ins.

Review grouping in the independent constructor guards, setup stages and CLI
dispatch when those functions are repaired. No broad rewrite or crate split
is established by these files. The emulator shell script forwards explicit
trailing arguments and replaces its process with the emulator. Numeric shell
edge cases remain candidates without a runtime reproduction.

The CLI's non-finite/negative hold values and process-global cold-boot opt-in
need separate caller-contract assessment. Zero hold may be valid. No arbitrary
timeout cap is proposed. Remote state after an adb timeout, command status
handling during cleanup, boot/property provenance and live emulator behavior
remain unverified. Reading the property files and cited text does not verify
external sources, downloaded binaries, a loaded snapshot or browser fidelity.
