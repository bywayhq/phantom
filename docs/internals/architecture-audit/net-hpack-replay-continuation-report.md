# HTTP/2 HPACK replay oracle continuation

Baseline df2ae9b7d87567907a2f273068220349dcd4750b. Completed `crates/phantom-net/src/http2/tests/hpack_replay.rs`, all 1,104 lines. Exact Git blob and working-file hashes are adjacent. Four remaining baseline files are H3 connection, connector, early_data and request tests. Source-only review; no execution or tracked edits.

The oracle uses a raw duplex peer, exact retained request blocks and captured stream IDs, rather than re-encoding expected bytes using the production encoder. Cookie and WebSocket sessions compare literal bytes. Proxy captures intentionally store representations/indexes/block lengths instead of bytes; the replay restores only the capture tool's known throwaway credential marker, marks it sensitive and compares exactly the observable retained shape. Documentation explicitly admits an equal-length Huffman flag is not observed. All background-request sessions with unknown encoder state are excluded deliberately. Expected nonzero per-family session counts and exact 306 total proxy credential field coverage prevent silent zero-observation success.

Cookie crumbs are rejoined only within consecutive cookie runs, preserving other field positions, then re-split by the recipe under test. Request pseudo fields are required and typed, selected schemes and extended protocol are checked. Actual classic CONNECT, extended WebSocket, forwarded and origin calls share one encoder per session. The peer sends captured SETTINGS either before the first request or after exactly the captured pre-ACK request count, preceding the response that allows later requests. When SETTINGS precede the first request the client waits for the parsed capability state, avoiding unsynchronized fake peer mutation. Requests use captured IDs and the peer status ends only request-ended streams. These tests replay initial request blocks and therefore do not dispose the separately noted trailer ordering/sensitivity gap.

Negative controls require that a never-indexed proxy credential fail specifically on HPACK representation comparison, and that a Chromium recipe fail a Firefox session first on stream numbering and then on block bytes after renumbering. Independent origin/proxy and extended-origin/extended-proxy controls check both first and second sensitive credential representation: origin remains never indexed twice, proxy is incremental then dynamic indexed at 62. This deliberately tests the fingerprint rule; it is not evidence of arbitrary credential disclosure in logs or cross-route cache sharing.

Whole-session 10 second timeouts wrap replay and the selected negative controls. The focused two-request origin/proxy control bounds each connection, send and peer join separately. Peer handles are joined on the ordinary comparison path and errors prefer a precise peer mismatch over the client failure it caused. Earlier failures or whole-session timeout drop handles without explicit abort/join; runtime teardown owns them. Captured frame lengths are capped at 1 MiB, HEADERS padding arithmetic is checked, and CONTINUATION type and stream must match. There is no separate aggregate block/continuation count cap under this trusted outgoing-input test oracle. HPACK integer/string shape helpers and hex parsing assume generated ASCII fixture contents, not hostile public parser input. Requests-before-ACK extraction treats absence of an ACK as all captured requests preceding it; this is a fixture completeness limit, not evidence the implementation fails its production SETTINGS contract.

No new supported production defect. Selected retained session replay is independently meaningful within the stated exact-byte and exact-shape boundaries; it does not establish every browser version, response encoding, trailer behavior or complete proxy block bytes absent from the source captures.
