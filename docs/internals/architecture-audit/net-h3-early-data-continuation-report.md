## Test contracts and observation boundaries

Server configuration explicitly chooses QUIC early-data allowance 0 or u32::MAX with an independent rustls server. Learning waits for an actual ticket, drops the learned connection and returns endpoint ownership. Direct connection and ticket polling are timed. The front/back loopback relay allocates sockets through reserved-port-aware helpers; each server datagram is forwarded by a separate delayed child task. Abort of the relay loop does not abort or join those sleeping children, which retain its front socket until their brief delay completes. Both H3 server helpers detach per-connection tasks, and tests abort listener handles on success without joining all children. This is test ownership coverage, not a new established production leak.

At 216-299, stateless and remembered-settings dynamic requests check early offering, resumption, accepted outcome, exact response status and production tracing tag `sent`. The plain clone resumes without early data. At 458-498, POST with a body and DELETE without a body return success tagged `after_handshake`. However, the server helper first awaits incoming.await (82/536) before accepting H3 requests. Thus these controls independently establish full-handshake success, connection early-data state and emitted tracing labels; they do not independently observe a specific request arriving before the handshake. The relay's 150 ms delay comment at 24-26 says the first flight always carries the request, which timing alone cannot guarantee under arbitrary scheduling. Existing separate early-stream hook tests provide more controlled ownership and admission evidence; none of this demonstrates a production violation. To claim actual request 0-RTT packet timing, observe a server early connection or decode outgoing early packets, with a barrier before permitting the answer, instead of relying only on production tags.

The remembered-setting downgrade control advertises 16,384 then 8,192 on two real connections. Accepted early data must cause the exact peer H3_SETTINGS_ERROR close and nonreuse. Corrupt remembered state uses a deliberately truncated SETTINGS frame, a timed connector result, typed Protocol with safe exact message and no served paths. Its comment also says no second connection attempt, but this helper does not count acceptances; the earlier source connection trace, rather than this assertion alone, supplies that boundary. Cache/name independence creates a fresh isolated cache and a different verified hostname, then positive original-name resumption. The route wording is an analogy to caller-chosen isolated caches, not an exercised actual facade route-key split.

Rejected early data must return exactly the EarlyDataRejected unprocessed marker, settle to rejected state and leave the same connection reusable. The replacement H3 session serves exactly the later GET and POST on connection index 1, without any extra recorded path; this is a concrete transport/request duplicate-send oracle. Another rejected-session control accepts lowered SETTINGS on the replacement session and remains open/reusable, with two exact recorded paths. Peer extension completion is bounded. Several direct send and early-answer waits are not individually wrapped in a timeout, so the file does not establish a universal bounded failure path.

RecordingConnection delegates all transport operations and records the first nonempty byte of each received uni stream exactly once with connection index and stream ID. Only the known one-byte critical types are decoded; longer reserved types become u64::MAX deliberately. It preserves pending and original bytes. This is a bounded type oracle for controlled outgoing streams, not a public arbitrary QUIC varint parser.

ClientHello added-extension control uses the separately reviewed fixture comparator and actual learned ticket; it does not claim unchanged random/key or payload bytes. Test-injected early ALPS establishes no metadata before handshake, expected ACCEPT_CH after acceptance and reuse. Truncated ACCEPT_CH/SETTINGS cases preserve specific safe messages, typed Protocol without an unprocessed replay marker, cleared metadata and nonreuse. A conflicting ALPS/control setting waits for nonreuse; unlike the downgrade control, it does not directly assert a peer-observed close code, so its name's close claim is stronger than its independent assertion. Production can_reuse is an originating identity plus health snapshot, not a reservation or wait behind request admission.

No new supported production defect. The early-request timing and peer-close observation limitations are candidates to qualify or strengthen test assertions, and must not be represented as execution failures.
