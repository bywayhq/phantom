## Ownership and shutdown

Concrete TcpOrigin holds the served counter, a stop sender and an existing
ConnectionPeer guard for its parent. QUIC parent uses the same canonical
guard. No new generic task owner or raw-field Option migration.

Every accepted TCP worker belongs to a JoinSet immediately when spawned.
Returned actual AbortHandles remain available to original observations and
identify the unfinished tasks the owner requests to cancel at shutdown.
Before shutdown, completed JoinError results are observed and retained.
At stop, the listener drops, abort_all requests termination, and
join_next_with_id drains every accepted task before parent completion.

Only cancellation for explicitly targeted unfinished IDs is ignored.
Already-completed cancellation/panic faults remain typed errors. Existing
finish_with_cleanup retains all encountered causes without stopping drainage
on the first error. ID bookkeeping does not distinguish two racing external
and owner abort requests beyond the owner's own explicit request.

finish299–344 preserves existing count deadlines. Both stop signals are sent
before awaiting the QUIC parent. Count/QUIC failures cannot bypass the finite
TCP parent join. Original single primary remains exact; a simultaneous TCP
cleanup fault is composed using the existing FixtureFailures owner.
Count failure requests QUIC parent abort and still gracefully stops TCP.

Abandonment drops parent guards, requesting cancellation. The TCP parent's
future owns its JoinSet, whose Drop aborts all accepted children. Drop does
not asynchronously join; the frozen controls must show actual task
destruction and peer socket closure before backup with the runtime alive.
