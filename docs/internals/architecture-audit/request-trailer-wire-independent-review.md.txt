## Actual observations and independent expected bytes

The two new HTTP/2 cases send static and body-produced trailers through the real connection upload. Their peer consumes the client preface, replies with SETTINGS, requires initial HEADERS to leave the stream open, observes DATA `data`, then requires terminal HEADERS with END_HEADERS and END_STREAM. It compares the entire HPACK payload against a literal expectation. Incrementally indexed `a:1`, never-indexed `b:2`, and incrementally indexed `a:3` using the newest dynamic name at index 62 yield the expected A/B/A sequence. A grouped A/A/B sequence or a missing never-indexed marker changes those bytes. The strict-shorter Huffman policy makes the single-byte name/value strings raw because their compressed lengths tie. The response is a literal static-index 204 HEADERS frame; the peer is joined after dropping the client connection.

The two new HTTP/3 tests each exercise static and body-produced trailers with separate real QUIC connections. The raw peer first sends independently spelled control SETTINGS: table capacity 4096 and blocked streams 16. It opens both critical QPACK streams, classifies three distinct client critical streams, accepts a request stream, requires HEADERS/DATA/HEADERS and an actual FIN, and compares the complete trailer field section. No decoder-produced HeaderMap is used as the ordering oracle, and no encoder under test generates the expected bytes.

For Stateless, the literal field sections have zero Required Insert Count/Base. RFC 9204 literal-name forms and the RFC 7541 Huffman codes give `a:1`, N=1 `b:2`, then `a:3`. For the selected Dynamic branch, the initial field section requires the preceding authority insertion; the trailer section requires insertion count 3, Base 3, and references relative entries 1 and 0 around the sensitive literal. Its literal 13-byte encoder-stream expectation spells capacity 4096, authority insertion, `a:1` insertion and `a:3` insertion. This distinguishes reusing the connection encoder from resetting state for trailers. The expected instruction prefix is correct independently of calling that encoder. The test does not drain the unending critical stream to establish an arbitrary later suffix is absent; its assertion scope is the observed prefix and exact terminal field section.

## Caller and encoder trace

`RequestBody::poll_frame` uses the declared trailer-name occurrence plan to recover A/B/A from a HeaderMap containing repeated A values, copying each selected HeaderValue sensitivity flag into RequestHeader. HTTP/2 `PreparedRequestTrailers` and HTTP/3 `PreparedTrailers` retain both the semantic map and ordered vector with sensitivity. Both static completion and body trailer frame branches call their respective `send_ordered_trailers` seams. The H2 frame encoder selects the ordered iterator. The H3 Header iterator preserves ordered fields and sensitivity before either stateless encoding or shared outbound QPACK encoding.

The dynamic request and trailer send paths wait for the outbound driver's readiness before encoding, so the literal remote SETTINGS is not a timing-only assumption. The local advertised zero decoder table capacity does not disable the separate outbound encoder configured from this peer's settings. The peer's response is stateless `:status 200`, so it requires no server encoder instructions or client dynamic decoding. The renamed legacy tests correctly describe their retained per-name duplicate/value checks instead of claiming cross-name order from a grouped map.

## Bounds, ownership and readability

The H2 operation has one absolute three-second deadline; the H3 operation has a five-second deadline per input case. Raw H2 payload allocation requires length at most 16384; raw H3 allocation requires at most 1024; QUIC varint decoding consumes at most eight bytes. Finite expected critical streams and fixed small request input prevent a zero-observation success. Request closure and response completion occur before successful peer joins. The H3 done channel prevents premature server close, and server close releases its retained critical streams. On an early error or outer timeout the peer JoinHandle is detached, but these tests have their own Tokio runtime: client/channel drops plus runtime teardown release tasks and sockets. They do not establish a reusable long-lived peer fixture cancellation contract.

The endpoint binds `127.0.0.1:0` through `phantom_testkit::udp::bind`, which retries Windows reserved-port error 10055 finitely while retaining other errors. No wildcard or fixed port is introduced. TLS trust uses the existing generated test identity and its explicit root with peer verification. The request authority `a` is intentionally separate from the TLS connection's trusted test server name; it selects the asserted QPACK authority bytes without weakening TLS trust.

The new H3 wire fixture has its own focused child module and the parent registers it with `mod trailer_wire;`. The H2 additions stay with the existing trailer tests. Input construction, peer observations, frame/varint reading and response/join stages have concrete responsibilities. No copied encoder implementation or new public helper is introduced.
