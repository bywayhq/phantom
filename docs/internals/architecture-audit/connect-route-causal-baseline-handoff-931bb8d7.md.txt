## Ownership and evidence limits

Both peers are ready through actual parsed wire observations, rather than
sleeps. The origin supplies literal POST bytes and the seven-byte payload.
The proxy supplies literal ordered CONNECT fields from its actual parser.
Each held-origin check consumes the complete response body before observing
the owner's boundary. A client handle remains live through backup cleanup.

Task destruction has a finite 150 ms observation per peer. The observation
is saved before releasing the origin or aborting backups. Backups then abort
both raw tasks and observe destruction within ten seconds. Already consumed
receivers are not repolled. Receiver errors remain errors. The guard is
created before spawning, and its destructor runs after each peer's stream
locals are dropped.

The transferred baseline handles cannot be joined after the defective owner
drops them. Backup markers establish destruction, not observation of their
discarded task result. Successful finish does observe the raw joins. Drop
fallback aborts on panic or external cancellation; it does not synchronously
join. No permanent socket-leak claim is made.

PermissionDenied 911 and Unsupported 912 are deliberately injected after
actual peer exchanges. The truncated response is real loopback TLS/HTTP.
Neither injected cause is presented as a native OS failure. The deadline
control advances the test clock and makes no network timing claim.

Controls capture fallible operations before backup cleanup. When both the
operation and cleanup fail, their original boxed causes are retained through
the existing `finish_with_cleanup`. Prerequisite assertions can still panic;
the abort guard is the fallback for that path.

The auth and remaining ordinary caller owners remain source findings. These
new controls exercise the actual first-upload path and shared bound, not an
entirely new fixture implementation or all public proxy behavior.
