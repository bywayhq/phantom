## Cause and remedy

The listener previously detached accepted connections, which detached stalled response tasks. Aborting the listener left response bodies, counters and connection observations alive. The accepted loop also discarded every `connection.accept()` error. The native baseline on each host reached all four intended assertions: three live-peer ownership observations and the actual remote H3_INTERNAL_ERROR source assertion.

The listener now owns accepted children in a JoinSet. Every accepted child owns responder tasks in a second JoinSet. Explicit finish signals shutdown, closes the endpoint and observes the listener result within the existing ten-second deadline. Children stop during TLS, H3 bootstrap, header resolution and response serving. Connection close happens before the pinned H3 future is dropped, preserving first-close ordering. Responders are aborted and joined; unexpected task, protocol and I/O causes survive with operation context. Completed failures collected before shutdown are retained.

Normal remote H3_NO_ERROR/application code zero and request H3_REQUEST_CANCELLED are classified narrowly. Local close is accepted only at the explicit owner-stop/drain paths. Intentional trust tests first require the concrete client certificate alert category, then permit only the identical server transport-close code. This does not waive unrelated TLS/provider failures.

Ordinary callers capture their operation result and then call explicit origin finish through the existing `finish_with_cleanup`. Single fixture clients/proxies remain in lexical Option owners representing successful construction, so setup/request errors still retain initialized peers through cleanup. Only actual repeated-client tests retain vectors of shared client handles and proxy owners. The diagnostic drop-counter test preserves its original explicit client Drop. Primary and cleanup failures retain separate typed objects.
