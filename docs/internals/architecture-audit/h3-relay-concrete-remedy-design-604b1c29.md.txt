# Concrete H3 relay cleanup design

Source-only design at signed, clean `604b1c29feabab924c5ef8afd00d07272f62330b`. The five new controls remain a causal forecast: one positive and four negatives. No target execution, compilation or protocol acceptance is claimed. The signed baseline and both standards follow-ups remain unchanged.

The delaying and gated factories return raw outer task handles. Dropping these handles detaches the coordinator. Both coordinators and their reply workers discard local receive/send errors, and the delayed-send tasks return unit. A completed receiver can therefore disappear while the front receive remains pending. `stop_relay` aborts and awaits only the outer task, suppressing any cancelled join; it neither reports completed unit-worker failures nor explicitly observes descendant joins. HelloSniffer already requests outer abort on Drop, but its unit coordinator/replies discard errors and its three callers only await the raw ScriptedServer task after fallible client work. These are fixture contracts, not library behavior or measured leaks.

Use a concrete private relay owner containing the existing `ConnectionPeer<TestResult<()>>` and a coordinator stop sender. Construction registers the coordinator eagerly. Drop requests abort through that owner; the coordinator's JoinSets own its descendants. Explicit stop sends one absolute five-second cleanup deadline, then observes the actual coordinator result under that same budget. Do not call `ConnectionPeer::stop` for the normal cooperative path: its cancelled-join suppression cannot establish cancellation provenance for this collector.

Each reply receiver and delayed send receives its own one-shot stop channel. Select the actual operation first with a biased selection, so a ready local fault wins over deliberate stop. Only a successfully received stop value represents intentional completion; channel disconnection remains a typed error. Preserve HelloSniffer's existing narrow ConnectionReset retry policy and the actual gate ordering and RELAY_DELAY. Stop discards pending held/scheduled replies as the existing abort path does; it must not flush new wire traffic.

The coordinator selects front input, completed worker outcomes and stop. Every receive, socket construction/connect, send and JoinError becomes a retained outcome. On the first failure, stop all siblings immediately. Collect available completed outcomes before signalling pending workers, then observe every remaining join under the shared deadline. Fold distinct outcomes using the existing `finish_with_cleanup` / `FixtureFailures`, including external cancellation and panic JoinErrors. A join is evidence; a successful stop send or JoinSet Drop is not. If the drain budget expires, retain the concrete Elapsed and earlier errors, then let remaining owned guards request abort. No observed destruction or total join beyond the budget is promised.

All six ordinary early-data relay callers need an eagerly owned finish operation capturing relay plus acquired server/request peers before fallible preparation and requests. Capture the client operation outcome first; combine it with server and relay cleanup while the client remains alive. Preserve each existing statement, response/wire assertion, gate and count timer. Apply the same pattern to all three HelloSniffer callers and change ScriptedServer's raw task to the existing concrete peer owner. HelloSniffer metadata parsing stays with its current owner; reuse a private relay lifecycle component only if it removes the actual repeated stop/join logic, not as a generic task framework.

The current five controls cover one client/reply worker and only the stated drop/completed-read contracts. Before broader repair credit, add small canonical-path controls for client-primary plus completed relay failure, two completed sibling causes, and sniffer local-error observation; retain real traffic, typed identities and pre-backup snapshots. External abort/panic, front send faults and reset-category controls remain separate until proved. A registry migration needed for two clients requires explicit control-scaffolding review. Adjacent raw accepted H3 serving tasks in timeout/concurrent tests remain a separate descendant slice; wrapping their outer server task alone does not close it.
