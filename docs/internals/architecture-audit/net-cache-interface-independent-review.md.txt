`crates/phantom-net/src/address_cache.rs:287: major: Receiver readiness is treated as stored-answer provenance after new/shared work can publish. Carry a Stored versus pending/new Answer decision made under the cache lock; do not derive provenance from current channel contents.`

Both TCP and QUIC callers use that flag. `direct::connect_tcp_with_lookup` gives a stored answer zero extra HTTPS-record wait, while fresh resolution gets a 5-50 ms allowance. `Http3Connector::connect_datagrams_ech` does the same. A fast published fresh answer can therefore change whether ECH is offered depending on scheduling. IP literals, overrides and inline work already explicitly report false. A deterministic test should select new/joined work, wait for its actual Publisher to answer, then consume it and still require false; a genuinely selected stored entry must report true.

`crates/phantom-net/src/socket_ffi/interface.rs:199: major: lookup_failed replaces a non-absence OS error with kind and text, losing the original code and typed cause despite the lookup and FFI audit documentation. Retain the owned error in concrete context and preserve it through source_binding::interface_error.`

Unix non-absence errno and Windows IP Helper failures reach this wrapper. The next source-binding layer stringifies again. Source-address `bind_error` at source_binding.rs:382-386 has the same cause-loss behavior and belongs in the bounded correction. Missing interfaces remain deliberately normalized NotFound; malformed names remain invalid input. Native failure injection has not been performed here. Pure raw-code and typed-source controls should prove that context and category survive while the original error remains recoverable.

`crates/phantom-net/src/address_cache.rs:148: major: Outcome discards a resolver error's original object and source chain, including the first shared or inline lookup. Retain one shared original error and deliver cloneable context that links to it instead of retaining only kind and message.`

This last finding needs a precise contract qualification. ClientBuilder::address_resolver at client.rs:1090-1093 explicitly documents the cached kind/message-only limitation. It is not an undisclosed old promise that every cache error retains its type. However, the supplied engineering standard requires preserving underlying causes; sharing alone is not an exemption. RequestError also tells callers to inspect source for original type/detail. An Arc-owned io::Error with a small concrete context can support all waiters without copying arbitrary resolver errors. A contextual outer io::Error need not itself return a raw OS code: the original nested error/code or custom get_ref value must remain accessible. Update the specific cache documentation when strengthening that contract.

The uncached resolver path propagates the original io::Error. HTTP/1 transport and facade error owners retain what they receive, but cannot recover an object already destroyed by Outcome. The corresponding HTTP/3 resolver owner also retains the supplied error. Tests currently assert kind, message and call counts, not original cause access. Meaningful added controls should use a caller resolver with an independent typed sentinel/nested source, cover first/joined/stored/inline cache paths, and separately check an OS-error sentinel. Preserve negative-TTL and A4 runtime/generation/reservation controls.
