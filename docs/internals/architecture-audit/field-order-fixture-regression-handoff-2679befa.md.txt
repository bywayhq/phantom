## Controls and forecast

With all features, select `test(proxy_field_order::)`: eighteen methods, eleven
predicted positives and seven predicted causal negatives. The JSON contains each
fully qualified name and the first predicted failure boundary.

- Deadline: actual paused-clock expiry retains the old context but loses Elapsed.
  Concrete inner error and ready-operation controls remain positive.
- Ownership: literal CONNECT/200 exchanges precede driven and unpolled caller
  cancellation. Destruction is captured before client close or backup abort.
  Bounded cleanup occurs before the captured false assertion. No permanent
  socket survival claim is made.
- Secondary cause: the actual recorder receives literal CONNECT and completes
  with a typed intentional failure. An injected typed caller failure then uses
  the same ordinary completion seam. Baseline loses the completed secondary.
  Both failures are controlled causes, not OS errors.
- Construction: an actual CRLF-invalid template is independently rejected and
  then skipped by the helper. The fixed URI builder guard remains source-only.
- Expected failure: actual literal 502 rejection must reach Proxy/Rejected502.
  Baseline discards it. Separate 200-close positives independently repeat the
  HTTPS and WSS opening and inspect retained TLS handshake causes.

writing 200, then client origin TLS setup mapping the actual backend failure into

chain, including btls::ssl::Error. No specific OS disconnect kind or backend
code is assumed. Native results must verify this source forecast. Later typed
