The tests neither fabricate TCP EOF nor substitute a second close-helper implementation. The generic seam leaves all ordinary TLS calls and read branches unchanged. These are read-policy controls, not observations of natural TLS/backend failures.

ReadPeer starts and immediately guards the sole original worker before connecting the caller. Its five-second Pending wait and unfinished-worker check precede every client action. observe awaits that original handle through a borrowed guard, so a timeout retains ownership. On completion it collects the worker's actual result once, removes the already-joined guard, then witness requires Pending, reader destruction and absence of an uncollected worker. It checks actual client EOF or the existing narrow peer-disconnect kinds before the caller evaluates its result oracle. All fallible operations have finite waits. Outside the primary result, stop explicitly aborts/joins any remaining worker and finish_with_cleanup retains both primary and cleanup failures. On unwind, the existing guard aborts; that Drop safeguard is not an asynchronous join claim.

The four new controls check real EOF success, rejection of a literal unexpected client byte, supported disconnect error kinds, and unrelated PermissionDenied retention. The supported-kind test iterates precisely BrokenPipe, ConnectionReset, ConnectionAborted and UnexpectedEof, matching the existing resolved is_peer_gone policy. The negative control requires the actual received PermissionDenied kind and its ReadFailure cause with Arc::ptr_eq against the original identity, after original worker completion/destruction/socket closure and before backup cleanup. Current Err(_) acceptance should instead yield the explicit missing-failure oracle. New source groups imports by origin, keeps its domain-specific observation responsibility separate from its tests, and adds no manifest, dependency, generic owner framework or production change.
