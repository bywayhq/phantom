## Findings

### EX1 (P2): Do not print cookie values

`crates/phantom/examples/cookies.rs:39-42`

request_value returns Option<String> containing the Cookie field. The code converts absent value to empty String then formats sent with String Debug; session=sensitive-value is emitted verbatim apart from string escaping.

Remedy: Report only whether a cookie field is present and/or jar count. Do not log the returned String, names or values.

Verification: Focused synthetic-cookie output assertion with a sentinel secret, absence/presence positives, followed by compile-check of cookies feature example at integration.

### EX2 (P2): Reject another origin before page I/O

`crates/phantom/examples/request_template.rs:31-34`

Url::join accepts absolute and // authority targets. The fetch factory installs sec-fetch-site same-origin for trustworthy origin and copies caller Referer; it does not compare target with page. No comparison exists in this example, so a foreign HTTPS URL is sent with misleading same-origin metadata after the first page request.

Remedy: Compare normalized page/fetch origins immediately after parsing/joining, before client creation or first send. Reject a foreign scheme, host or effective port. Keep legitimate relative and same-origin absolute targets.

Verification: Pure input controls for relative, absolute same origin, effective default port and foreign scheme/host/port/network-path negatives; prove the guard runs before client/I/O. Compile-check at integration.

### EX3 (P2): Keep query fields out of status diagnostics

`crates/phantom/examples/request_template.rs:49-60`

Both success println statements interpolate complete Url. A valid supplied ?token=sentinel remains in the printed URI. This is concrete accepted caller input copied to diagnostics, not a claim that userinfo/fragment is sent.

Remedy: Print operation plus status and optional origin only; omit path/query from diagnostics. Keep path/query in same-origin HTTP target and caller-owned Referer.

Verification: Pure diagnostic formatting assertion rejects query/path sentinel while keeping useful operation/status; ensure URL request/Referer bytes are otherwise unchanged.

### EX4 (P3): Point to the current template guide

`crates/phantom/examples/request_template.rs:4-4`

Module rustdoc names docs/guides/profiles.md for Apply a captured request template. That heading lives in docs/guides/request-templates.md at this commit.

Remedy: Correct the module documentation path.

Verification: Source pointer check and repository documentation checker at integration.

### EX5 (P3): Apply import and guard grouping standards

`crates/phantom/examples/quic_interop/main.rs:22-26`

Local use declarations follow module declarations; five independent target validation guards are packed without blank paragraphs. Attached standards prescribe imports before module declarations and visually separated guards. No runtime correctness defect inferred.

Remedy: Move local imports ahead of mod declarations and add blank paragraphs between independent target guards, without splitting domain owners or changing behavior.

Verification: Targeted rustfmt check plus diff review; no mirrored tests for paragraph-only edits.

## Qualified boundaries

- No credentials/fragment Referer exposure established: initial Client::get delegates to parse_absolute_uri, which rejects # and @. A credential/fragment page fails before send, success diagnostics and Referer construction; invalid fetch fails its own get before fetch send/println. The current example may already have performed page I/O for an invalid fetch.
- The fetch template deliberately has a caller-owned Referer slot. Its expansion copies caller values without browser referrer-policy derivation. Same-origin path/query belongs to this caller input contract; no query-stripping remedy is proposed for the Referer. Cross-origin rejection is required by this example advertised task.
