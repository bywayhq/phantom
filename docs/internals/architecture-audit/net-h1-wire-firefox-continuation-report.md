## Observable contracts

- `http1/tests/reuse.rs` (1–663): real in-memory peer checks two exact request heads and distinct ordered response headers on one connection, owned/streaming POST then GET, and bodyless HEAD without framing. A 50 ms peer window plus a blocked later task proves no pipelining while the current response body is retained; after consumption it proceeds. Incomplete response drop invalidates reuse. Peer-observed dispatch barriers precede task abort, and request task join plus peer EOF prove cancellation closes the stream. A permanently pending upload uses an independent source Drop flag, with a 1 second release wait, no extra peer bytes and nonreusable state. Immediate source error and mismatched dynamic trailers prevent trailer content/final chunk and invalidate reuse. Request close token, HTTP/1.0 even with keepalive, and EOF framing are excluded from reuse. Empty-response failure on a reused connection has a distinct typed category and retains the actual backend source; fresh and partial-response failures remain Protocol. All peer tests use the previously reviewed whole-test bounded wrapper. They join peers on success; early failures still leave peer handles to runtime teardown. No socket platform behavior is claimed from duplex streams.
- `http1/tests/request_wire.rs` (1–1250): independent byte literals assert complete request-line/header order, spelling, interleaved duplicates, generated Content-Length/Transfer-Encoding positions, known and unknown streaming payload/framing, absolute-form proxy requests and explicit length spelling. Both static and body-produced trailers compare the complete interleaved wire bytes and declared casing/order; this is stronger than the already noted H2 semantic-map trailer oracle, and does not establish H2 HPACK sensitivity. Trailer-only requests are chunked. Typed validation rejects conflicting trailer sources/declarations, forbidden trailers, count/byte excess, mismatched and duplicate/noncanonical length, explicit framing and critical Connection nominations. PollCountingBody plus attempted-write count establish zero source polls and zero attempted application writes for selected invalid inputs; the wrapper does not count reads, flushes or shutdowns, so test names saying touches the stream should be read with the source preflight trace rather than as an independently instrumented all-I/O assertion. One-byte peer reads exercise interim 100/103 separation, final headers, global ordered response casing/duplicates and normalized OWS. Literal malformed response preserves its direct backend source and specific tracing outcome; invalid preparation emits one error span and no response span. Task abort after peer head observation proves EOF. Whole bounded wrappers apply to peer tests; direct preflight paths return synchronously under the source contract. No new arbitrary input parser was introduced by the trusted Chunks/body fixtures.
- `http3/tests/firefox.rs` (1–876): independent frozen Windows captures compare cipher/version/group/signature/ALPN/SNI vectors, selected extension bodies, shuffled extension membership with a fixed QUIC/ECH tail, exact transport-parameter order and encoding widths, stable bytes excluding per-connection CID/reserved version. Three live uni streams establish IDs/types control 2, encoder 6, decoder 10; exact SETTINGS bytes and the reserved frame rule are observed. Resumed ClientHello comparison requires at least three selected captures, PSK last and early-data extension, and applies a separately reviewed NSS length model while documenting server-dependent ticket/binder length. Recording helper explicitly allows a failed handshake and keeps the client owner until the server sees its hello, so it proves offer bytes rather than completed authenticated requests. IPv4 literal capture comparison and uncaptured IPv6 padding inference are explicitly separate. Silent loopback socket reads exactly two Initial datagrams and compares sizes/version/CID lengths; IPv6 Initial size 1,232 is source-backed, not capture-backed. Reserved-port-aware helpers cover all new endpoint sockets. The v2 relay authenticates/decrypts v1 Initials, reprotects their payload under independent rustls v2 keys, and the v2-only server completes a response while a nonzero client v2 packet counter is required. Source-binding/client-certificate connector preserves Initials and version transition, but the server does not request a client certificate, so this does not claim mutual authentication. Actual fixture request compares method/path/probe and full body. Relay/initial attempt handles are aborted on success without joins and lack guards on all early returns; normal whole-operation or per-datagram deadlines are present. Helpers index packet fields under trusted generated traffic assumptions, not hostile peer acceptance semantics.
