## Result and exact scope

The decoder already retains ordinary fields in their decoded order. The
request conversion previously discarded that owned vector. It now returns
the existing `Option<OrderedHeaders>` alongside method, URI, protocol and
semantic headers. The server resolver inserts that value into the received
request's extensions. It preserves `Some(empty)` for a decoded request with
no ordinary fields. It neither rebuilds the order from `HeaderMap` nor changes
the decoder, pseudo-header validation, outgoing encoding or response path.

Only four tracked files changed:

- `vendor/h3/h3/src/proto/headers.rs`: conversion and two package controls.
- `vendor/h3/h3/src/server/request.rs`: tuple adoption and extension insertion.
- `vendor/h3/patches/ordered-received-request-headers.patch`: canonical patch.
- `vendor/h3/patches/series`: one entry immediately before publish identity.

The source snapshot was changed by applying the recorded canonical patch.
There is no unrecorded vendor source edit. Manifests, lockfiles, PHANTOM notes,
public documentation and CHANGELOG remain integration-owned and unchanged.

## API qualification and packaging

`Header::into_request_parts` is private through the normal module tree, but
public under the existing
`i-implement-a-third-party-backend-and-opt-into-breaking-changes` feature.
Its return type changes from a four-element tuple to five elements, adding
`Option<OrderedHeaders>` at the end. This is a source API change for those
opt-in consumers. No compatibility shim was added. The initial subject lacks
`!`; the integration owner was notified before handoff and owns the final
breaking-change subject and migration disposition.

Suggested user-visible entry: “Received HTTP/3 requests retain ordinary
header order, including interleaved duplicates, in `OrderedHeaders`.”
Suggested Migrate note: “When using the H3 backend opt-in feature, destructure
the new fifth `Header::into_request_parts` element for `Option<OrderedHeaders>`.”

PHANTOM requires increasing the fork suffix when its source changes. Root
must update the publish-identity patch, package pins/locks, package notes and
any release entry before accepting the complete package. This lane has not
performed that packaging work or the full upstream archive replay.
