# Net address, proxy, and platform standards review

Request changes: one DNS provenance race and one interface error-preservation mismatch.

Exact source: `6535bd75b9d148832afe26888f56aa3cdef6b256` in `C:\code\phantom-worktrees\architecture-audit`. All eight requested production files were freshly read in full, including every platform branch. Their total is 2377 lines. This is a bounded source review, not whole-project completion or runtime approval.

## Findings

### NET-ADDRESS-F1: Fresh DNS publication can be mislabeled as a stored cache answer (P2)

Answer::Wait combines a locked stored-entry decision with newly started/shared resolution. After spawning concurrent work, lookup_noting_cache infers stored from receiver.borrow().is_some(), so completion before that borrow yields true for a lookup that performed resolution.

connect_tcp_with_lookup gives a true stored flag ZERO extra HTTPS/ECH record wait rather than the fresh lookup allowance clamped to 5..50ms. A fast answer can therefore change ECH lookup selection/handshake behavior depending on scheduling.

Remedy: Carry explicit provenance in Answer or a stored-answer variant, assigned while selecting the cache entry under its lock. Both newly started and joined pending resolution remain false regardless of channel readiness.

Regression: Force actual new/shared resolution publication before its Answer receiver is consumed, then assert false; stored entry positive true, inline/IP/override false. Add composed bounded HTTPS-record allowance positive when useful without timing-only probabilistic loops or production hooks.

Status: confirmed by complete source and caller reading; no execution.

### NET-INTERFACE-F2: Non-absence interface lookup failures discard the original OS error (P2)

lookup_failed takes &io::Error but reconstructs only kind plus formatted String. Every non-absence Unix/IP Helper lookup failure loses raw OS identity and its original typed cause. source_binding interface_error also replaces error with text at the caller boundary.

Callers see a readable kind/message but cannot recover the underlying OS code/cause. index rustdoc promises the OS error on lookup failure and the design audit says other failures keep it.

Remedy: Return the original OS error where context is unnecessary, or retain it inside a concrete contextual Error owner/source. Preserve it through the source-binding wrapper as well; keep intentionally normalized missing-interface NotFound separate.

Regression: Use distinct io::Error::from_raw_os_error sentinels through the contextual wrappers; require original code recoverable in retained typed cause, original category and contextual text. Positive normalized-absence and malformed-name controls remain independent of host failures.

Status: confirmed source preservation/doc mismatch; no OS fault injected.

## Manual source and test assessment

The eight modules have concrete domain names and a shallow owner-oriented layout. State-machine and FFI functions serve coherent responsibilities; the larger cache/pool functions coordinate one bounded operation rather than hide unrelated side effects. Existing long test modules live under their owner domains. Arbitrary size alone was not treated as a defect. No crate split or API redesign is justified by this pass.

Cache locks are released before resolver work and awaits. Publisher drop releases reservations. Custom lookups are scoped per runtime, while blocking system resolution deliberately survives request cancellation. Clear prevents stale publication and preserves the shared-work bound. F1 concerns answer provenance, independently of those lifetime safeguards.

Proxy caches partition configured credentials and redact their values. CONNECT drains have a 64KiB framing-inclusive bound and deliberately discard unusable connections. The caller owns elapsed timeouts. HTTPS proxy identities reset on connection-shaping builder changes, and tunnel leases remain until stream completion/drop. Pool setup failures remain with the waiting attempt; cancellation frees setup and wakes waiters.

TCP races keep at most two lexical futures and drop the loser. Keepalive state changes precede the next stream bytes, and applied state changes only after successful OS operations. The connector verifies its process-lifetime deadline service before a schedule is created. Unrepresentable durations intentionally never expire.

The FFI uses terminated local strings, initialized local LUID/index values, borrowed open sockets and four-byte buffers. It checks returned sizes/statuses and exposes no raw-pointer API. Source binding filters families without an unbound fallback and sets interfaces before bind/connect. Address-interface agreement and DNS binding remain explicitly caller-owned limits. Windows and Unix/error branches were read, not executed.

Supporting tests include literal CONNECT requests, independent connection counts, scripted dial start/cancel observations, a live resolver-future counter, cache generation checks, setup-failure histories, and native option readbacks. They do not test readiness-independent DNS provenance or retaining original interface error causes. Test source reading supplies no passing result.

## Rejected candidates

- Unbounded shared async DNS tasks: Not established: shared_resolutions counts even clear-detached work, bounded by max_entries; past-bound caller async work is owned inline. Blocking pool concurrency and queue distinction is documented.
- Proxy credential cross-route leak: Not established: cache is a configured-credential presence decision, not a credential supplier. Keys include scheme/host/port/full credential; Debug only counts.
- Pool lost notification or later error overwrites a waiter: Not established: notified future enabled before locked check; per-attempt watch receiver retains its failure; cancellation drop wakes. Supporting tests directly assert these contracts.
- Timer service silently unavailable on production keepalive start: Not established: connect_resolved_keeping_slower rejects unavailable service before creating a schedule; slower schedule originates from that connector path. Unrepresentable Instant durations intentionally never expire.
- Winsock last_os_error is the wrong retrieval API: Rejected as unsupported: installed socket2 0.6.5 itself uses same immediate last_os_error pattern. No contrary native result or authoritative boundary evidence retrieved.
- Interface pointer escape, initialized value violation, endian mismatch, or bind after connect: Not established: local terminated buffers and BorrowedSocket lifetimes remain in call, LUID/index initialized and statuses checked, four-byte lengths checked, both family encodings match caller and readback contract, interface options precede bind/connect.
- Chunk extension/trailer grammar tolerance necessarily permits unsafe replay: Not established: decoder is a bounded discard-only boundary parser, not full semantic trailer validator; malformed CRLF/size and trailing unsolicited bytes reject reuse. Full strict grammar parity was not assumed or researched.
- Counter overflow after 2^64 updates requires immediate architecture refactor: Not filed: theoretical horizon alone does not establish practical observable failure within task scope; no broad speculative refactor proposed.

## Verification and limits

- No Cargo, compilation, Clippy, tests, native socket/network, OS failure injection or gate run was performed by this reviewer. Exact source review is not runtime/platform execution proof.
- Historical reconciliation was read only as retained metadata; it supplies zero fresh full-read credit. All full source records above come from fresh committed reads at the specified revision.
- Working HEAD advanced during reading; every source record remains bound to immutable 6535bd75, not current working bytes. No source edit or tracked evidence import was performed.
- Broader platform availability (iOS/visionOS/etc), browser citations/parity, sanitizer coverage and all HTTP2 vendor/caller behavior were not newly verified. Platform branches were manually inspected, not executed.
- AddressCache Outcome clones ErrorKind plus message, discarding typed resolver source even for the first waiter. This is an explicit cause-retention limitation, separate from F1; tests assert kind/message only. A cloneable Arc-owned resolver error could preserve sources, but no existing public source-preservation test contract was assumed.
- Supporting TCP/UDP test observers use error-to-false getter defaults; failed getter cannot substantiate an unset-option assertion. This pass does not file or remedy a separate outside-scope observer defect.

Only new ignored scratch artifacts were written. The integration owner owns remediation, imports, baseline/corrected executions and final gates.
