Its caller awaits the peer setup task and body, but never joins this connection driver or observes its panic/protocol-error result.

Proposed remedy: Return an owned driver handle alongside the count, retain it through response collection, drop the client connection and join its typed completion under the existing absolute deadline; ensure failure-path ownership aborts a still-live driver.

## Qualified and rejected candidates

- H2 final DATA could swallow queued trailers: rejected by resolved source. vendor/http2 recv is_end_stream requires receive end AND pending_recv empty; share.rs documents both poll_data and poll_trailers absent. Selected response_body tests require actual trailers.
- Ignoring H2 release_capacity necessarily hides a network failure: qualified invariant. Resolved release_capacity only rejects releasing more than in-flight receive bytes. This body owns the RecvStream and releases exactly the just-returned DATA length once; callers cannot manipulate that flow-control object. An inline explanation could make this reason clearer, but no reachable new failure was established.
- Detached H1 supervisor / H3 body task implies an unowned socket leak: rejected as a blanket claim. H1 terminal signal supervises abort+join on origin runtime. H3 cancellation and demand channels plus reset grace own the task lifecycle; absent terminal event is explicit error. Overflow datagram-notification child retains only a bounded event/error sender, ends when body receiver drops, and does not retain QUIC streams or admission guards. No fresh runtime proof is inferred.
- Single retained-guard slot violates current facade admission: qualified interface limit. H1/H2 retain hooks replace the previous boxed guard. Selected facade body constructors call each once; no current double-assignment path established. Multiple-call semantics should be documented or constrained if exposed to a new consumer, rather than claiming a demonstrated permit-release defect.
- Capsule encoder silently accepts arbitrary invalid types: qualified private precondition. varint encoder returnsfalse above62-bit MAX; capsule encode does not inspect that bool. Current production callers use DATAGRAM constant and bounded payload; tests use representable unknown types. This review does not approve arbitrary external capsule-type inputs or32-bit gigantic slices.
- Future budget test proves maximum runtime stack use: explicit evidence limit. It measures future object sizes in debug tests without calling network operations. Poll-frame peak/runtime scheduling/OS stack behavior require separate measurements.
- A passing typed-body/status/path oracle establishes task teardown: rejected for NB1. Actual delivery proves the required upload/body behavior; detached driver terminal state remains unobserved. Ownership/teardown is a separate contract.
