# Android async lifecycle design

At frozen `820b17d31131e49f2fd41c050c88926fb1f2307f`, Android startup and shutdown can block the capture event loop. Changing only the entry condition is incomplete: the worker path's completed-entry cancellation branch, BrowserDriver exit, and unauthenticated Android proxy-driver exit still perform synchronous cleanup on that loop.

The existing shield and lock establish a single cleanup owner. Preserve the actual executor Future, exact same-coroutine cancellation and abandoned-worker failure reporting. Caller cancellation does not terminate a running worker, and caller completion does not prove worker-operation completion. Existing launcher body-primary aggregation already works; the separate AndroidSession cleanup findings remain separate.

Use a finite real host child behind a narrow test-adb command adapter, with no device claim. An external monitor owns its gate before canonical entry starts. After the actual selected command signals readiness, the monitor posts a real loop callback and records whether it ran while the child remained held, then always releases the gate. An eventual callback after release cannot satisfy the pre-release progress oracle. Retain actual child, stream and monitor ownership; observe submitted worker-operation completion and exact raw failures before independent backup.

Separate startup progress, shutdown progress and healthy worker completion controls first. Cancellation controls must capture the error escaping the canonical await inside the same coroutine, preserve shielded worker ownership, then observe completion and cleanup/report association before backup. If a progress prerequisite fails, later cancellation oracles remain uncredited. Use actual scheduling witnesses for completed-entry races, not guessed sleeps.

The smallest owner repair needs a concrete async exit as well as owned entry. Use it in BrowserDriver and the unauthenticated Android proxy-driver cleanup path, preserving remote-before-browser order and existing error policy. A worker exit Future must remain strongly owned through cancellation or an explicit completion observer must retain its outcome with the initiating cancellation/body failure. Root must choose that cancellation timing contract; this report introduces no global deadline. Direct android_run remains intentionally synchronous.
