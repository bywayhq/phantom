## Confirmed findings

### MS1: Stream MASQUE proxy Drop leaves accepted connections and relay children alive (P2)

`crates/phantom/tests/support/masque.rs` ranges [[483, 498], [522, 526], [611, 640], [698, 735]].

spawn_with_alpn discards each accepted connection JoinHandle. serve_http1/serve_http2 additionally discard reader/writer/driver handles. Drop aborts only the listener task and there is no stream-leg watch cancellation. Tokio 1.53.1 dropping JoinHandle detaches rather than aborting its task.

A running proxy advertised as aborted on Drop must relinquish its accepted connections and relay sockets when its owner is dropped, including when the surrounding bounded test is cancelled.

Keep an established H1/H2 CONNECT-UDP client/inner connection alive, drop MasqueStreamProxy, and continue exchanging packets; detached read/relay tasks still own socket halves and UDP relay. Or hold a TLS handshake open, drop proxy and observe accepted TCP resource remains. This is a source-established lifecycle, not a executed reproduction.

Repair: Keep connection tasks under a JoinSet owned by the accept-loop task, and keep driver/read/write children under the connection owner. Abort/drain or close them on owner cancellation; preserve ignored expected packet-loss/peer-close policy explicitly.

Verification: Independent controlled peers: positive relay before drop; after proxy drop while client remains live, accepted transport closes and no datagram is relayed; test stalled TLS and partial capsule, and cancellation of outer bounded future. Track actual accepted child cleanup rather than sleep/count-only evidence.

### MS2: H2 capability oracle treats protocol errors as proof no request was sent (P2)

`crates/phantom/tests/support/websocket_origin.rs` ranges [[100, 121]].

Both the initial accept branch and post-client_done branch map any Some(Err(_)) to false. A parser/protocol failure caused by bytes sent by the client therefore satisfies the same no-stream result as idle timeout or orderly closure.

h2_websocket_over_proxy_requires_peer_setting claims no extended CONNECT HEADERS were sent before the peer capability. Unexpected protocol failure is not independent proof of absence.

After normal TLS/H2 setup, inject a malformed request/protocol frame: accept yields a protocol error, helper returns Ok(false), caller !origin assertion passes. Client-side error category Http2 can also match the current caller assertion. No injected test was executed here.

Repair: Propagate unexpected protocol/parser errors and observe attempted HEADERS independently where the peer decoder can reject the stream. Keep explicitly classified normal close/quiet-window outcomes separate.

Verification: Positive forbidden-HEADERS injection must fail the no-request oracle, including malformed/rejected HEADERS; clean client capability refusal must still pass after a real observed handshake/settings exchange.

### MS3: H1 echo helper accepts a non-Close second frame (P2)

`crates/phantom/tests/support/websocket_origin.rs` ranges [[160, 173]].

echo_h1 reads the second ClientFrame and emits a Close with its payload without checking close.opcode. The H2 sibling checks opcode 0x8.

The helper says it answers the client Close, and selected exchange_echo callers assert a Close reply with the supplied code/reason. A reply invented for Text/Ping/other opcode does not establish that client Close framing was correct.

Send a second masked Ping frame carrying bytes equal to the intended Close payload: H1 helper emits a valid Close and returns success. A client opcode regression can pass the current Close-response assertion. No injected test was executed here.

Repair: Require the observed second opcode to be Close before replying, and retain observed payload/code expectations in callers.

Verification: Controlled H1 peer sends Text and Ping as second frame and helper fails; actual masked Close with expected payload succeeds. Check H2 sibling remains consistent.

### MS4: HTTPS WebSocket relay rejects a normal Windows abort during teardown (P3)

`crates/phantom/tests/support/websocket.rs` ranges [[128, 149]].

The relay accepts ConnectionReset and BrokenPipe as peer closure but returns ConnectionAborted. The same support tls::is_peer_gone recognizes all three, and the repository Windows agreement requires all three for disconnect tests.

connects_through_verified_https_proxy awaits proxy result after successful Close exchange; platform-specific normal closure must not turn that positive wire test into failure.

copy_bidirectional returns ConnectionAborted after client/peer teardown; helper propagates Err although reset/broken-pipe for the same state are accepted. No Windows socket reproduction ran here.

Repair: Use the shared peer-gone predicate or explicitly include ConnectionAborted; retain propagation of unrelated I/O failures.

Verification: Independent error classification controls cover abort/reset/broken-pipe versus unrelated error, plus the actual HTTPS proxied Close test on Windows and Linux.

## Dependent oracles and layout

The selected capability test at `streams/websocket_http2_proxy.rs:276` consumes MS2; its H1-in-H2 and plaintext echo tests at 393/438 consume MS3 through `exchange_echo`. `streams/websocket/routing.rs:908` consumes MS4 after a real Close exchange and exact CONNECT/origin request assertions. `http3/connect_udp.rs:672/713` consumes the MS1 stream proxy through exact response, request, capsule and connection observations. Its existing bounded wrapper aborts the main test future after 30 seconds, which does not abort detached child tasks.

The support directory already groups protocol/domain owners. The long upgrade fixture has a distinct nested raw HTTP/2 responsibility; the stream and datagram MASQUE legs differ in flow-control and shutdown and do not warrant a universal proxy abstraction on this source evidence. Only SOCKS5 UDP has small inline parser tests, which meet the placement rule. Multi-binary test support justifies the existing dead-code allowance. No crate split, public API extraction or wholesale module reorganization is supported by this bounded pass.

Header digests and simple header lookup are duplicated between two WebSocket helper owners, but their frame-limit/RSV responsibilities differ. A small domain-owned consolidation may be reasonable after fixing the actual contracts; it is optional cleanup, not an independent correctness finding.
