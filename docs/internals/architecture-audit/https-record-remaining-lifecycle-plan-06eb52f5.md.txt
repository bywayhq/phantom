first failed join. An intervening accept failure can also drop earlier handles.
Three ordinary outer servers are raw tasks; later preparation/request errors
or outer cancellation can detach them. The proxied test already guards its
two outer peers, so it must not receive the same raw-detach diagnosis.

First drive a canonical TLS GET and literal 200/HTTP1.1/ok exchange, then
observe a genuinely Pending second accept/handshake. Retain Client, TCP and
runtime outside cancellation, and observe the actual worker destructor before
finite backup. An explicit-abort positive distinguishes unsupported ownership
from a control that cannot observe destruction.

For completed-result retention, mechanically extract the existing parallel
acquisition/collector while preserving old behavior. Drive all actual clients
through its barrier; after successful canonical response completion, supply
two distinct owned typed I/O outcomes from those same workers. Require actual
finished-worker and successful-response witnesses before testing both cause
identities. These controlled post-success errors prove collection, not OS
failure classification. Guard actual tasks eagerly and aggregate all explicit
cleanup results only after causal execution.

## QUIC origin and TCP fallback

`QuicOrigin` has raw parent/TCP handles and no Drop owner. Its count/parent
errors can skip TCP cleanup; successful finish requests TCP abort without an
awaited result. QUIC serving children are raw, aborted without result collection
on shutdown, and can detach on an internal early error. `serve_tcp` detaches
its TLS children and ignores accept/read/write/shutdown failures.

The QUIC watch count increments before serving begins. A count witness cannot
substitute for successful H3 serving completion. One baseline should use a real
with-TCP GET/200/HTTP1.1/ok and served count, then a retained second actual
TCP/TLS connection to observe parent/child cancellation before backup. Another
should perform real H3 GET/200/ok exchanges, wait for canonical `serve_one`
completion including response finish/close, then expose distinct completed
typed outcomes to the unchanged collector. A pending incoming-handshake
control is a separate parent contract.

After red evidence, reuse concrete guarded tasks for both parents and all
children. Close relevant endpoints and request all live shutdowns before
bounded waits; retain completed outcomes and qualify requested cancellation.
Endpoint close has an explicit API; endpoint-reference Drop merely wakes its
driver and does not establish joined cleanup. TCP serving must return typed
results while preserving the intentional rejected-ECH path. Shared
`try_handshake` currently maps failed or timed-out TLS to `None`; tightening
that shared classification requires a separate assignment and actual cause
evidence. No general rejection/error suppression is proposed.

Root's separate A184 local-address acquisition and outer `EchDeadline`
changes are not in this historical lane. Preserve them during composition.
The count-deadline baseline stays frozen and synthetic: it exercises actual
finish/watch ownership, not a constructor or handshake.
